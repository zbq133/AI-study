## 2026-11-02 补记：两条铁律怎么落到代码里

1. 「独立解题验证」升级为**两次独立解**：第一次按原顺序，第二次把选项左旋一位再解，两次必须指向**同一个选项内容**（不是同一个字母）。同模型重解只能证明自洽，打乱顺序才能查出「按位置蒙」的题。理由：验证器与被验证者是同一个模型，一致性不等于正确性，打乱是零成本能拿到的那一半证据。
2. 答案抠取加正则：验证模型常回「答案是 B」「B. 乙」，原来直接 `.strip().upper()` 比对会把**合格题误杀**。现在从自由文本里收字母串，越界字母作废；填空题没有选项可打乱，按去掉空白后的文本比对，不走字母抠取。
3. 引用校验加**行序检查**（`schema._reading_order_ok`）：同一页里行的 y 坐标应一路往下走，出现大幅回跳只可能是换了栏或跳到了另一段 —— 双栏排版里「左栏末尾 + 右栏开头」拼成一句正好是子串，但那是两处文字，必须丢。这是「不许拼接两处」从提示词挪进代码的部分。同栏相邻两行的边界拼接仍无法与合法引用区分，接受这个边界。
4. 新增测试一律做**变异验证**：把 y 容差关掉、把打乱换成恒等置换、把填空换回字母抠取，对应用例必须变红，否则视为无效测试。

## 2026-11-02 补记：OCR 落地（PPT 图片型课件）

`第十章 波动.pdf` 全量 OCR 跑通后补的四条。

1. **OCR 引擎选 RapidOCR（onnxruntime）**，不选 Tesseract：免装系统程序、中文模型自带、`pip install` 就好。代价是它只吃 3.12/3.13 —— 项目 venv 原来建在 3.15 上，`onnxruntime` 没有 3.15 轮子，`pip` 直接 `ResolutionImpossible`。**venv 已重建到 Python 3.12.10**，旧环境留在 `.venv-315` 可回滚；`requirements.txt` 顶部写明了这条限制。一页 200dpi 约 10 秒，12 页课件约 100 秒，结果按 `doc_id` 缓存在 `out/ocr/<doc_id>/pN.json`。
2. **OCR 只兜底"整页提不出文字行"的页**，有文字层的页永远走原生提取。理由：原生层带字号和 Bold，几何可信；OCR 的 `size` 是从框高估出来的（`_HEIGHT_RATIO = 0.86`），`bold` 一律 False。混着用会让同一份文档的标题判据自相矛盾。`DocIR.ocr_pages` 记下哪些页走了 OCR，下游能据此降低对字号/层级的信任。
3. **OCR 页不套教材章节的启发式**。第一版直接复用"字号大于正文就叫标题"，在真课件上产出 16 个伪标题：竖排侧栏标签（`两类波的不同之处`，宽高比 0.1）、示意图里的框内文字（`波源`/`介质`/`E 弹性模量`）、公式碎片（`u===v`、`=-=Tu`）、被 OCR 切成单字的列表序号（`曰反射`）。根子是 **OCR 的框高不可靠**，任何基于字号阈值的判据在 OCR 页都站不住。改成「**一页一章**」：PPT 的语义单元本来就是页；页首那一行满足 `_plausible_title` 且落在页面上 35% 以内才用它当章名，否则合成 `第 N 页`。12 页课件现在稳定产出 12 章。
4. **`_plausible_title(text, ar)` 三条下限**（`_MIN_TITLE_AR = 2.5`、长度 2..42、不以 `_SENTENCE_END` 结尾）同时服务原生页和 OCR 页；OCR 页额外要求页首标题不含冒号 —— `纵波(Longitudinal Waves)：质点振动方向与波的传播` 这种是"标题+正文"被 OCR 并成了一行，宁可退回 `第 N 页` 也不要把半句正文当章名。

**已知边界**：公式 OCR 不可用（`ν=1/T` → `v=1/T`、`u=λ/T` → `u===v`、`λ` → `入`），带公式的课件讲义会丢公式，只能靠模型从上下文补。这是产品需要直说的一条限制，不是待修的 bug。

两处新判定（OCR 页专用分支、宽高比下限）都做了变异验证：把 OCR 分支关掉、把 `_MIN_TITLE_AR` 改成 0，对应用例全部变红。测试 31 → 33。

下一轮待办调整：① 段落合并（仍然 1 行 = 1 块）；② `_render` 的 18000 字硬截断；③ 参考文献段过滤；④ `.env` 还没配，生成段一次真跑都没做过。

## 2026-11-03 补记：跨页重复行当页眉页脚摘掉

上一轮把页眉的**位置**修对了，但文本还在：14 条 `C. Wang et al.` 仍然留在 9 个章节的正文里，会随 `_render` 一起喂给模型。这一轮补上摘除。

四条门槛一起上，宁可漏掉也不误删正文：

1. 归一化（压空白、转小写）后逐字相同；
2. 至少 3 页、且至少占全文 20% 的页数上出现 —— 同一页重复几次不算；
3. 归一化后不超过 80 字 —— 再长更可能是正文小标题；
4. 每次出现都在该页的**最上一行或最下一行**（容差 1pt），而且这个文本**从没**在页面中部出现过。

第 4 条的后半句是豁免条款，也是这条规则里最关键的一处：只按"每页最上一行 + 跨页重复"删，会把正文里引用的标题（`Key Findings` 这种）一起带走。只要同一文本在页面中部出现过一次，就认定它是内容，不删。

顺序：放在 `NoTextLayer` 检查之后、算 `base` 之前 —— 先摘干净，字号基准和段落合并都不会再被这些每页重复的短行带偏。

实测（综述 15 页）：判定出 2 条（`c. wang et al.`、`resources, conservation & recycling 218 (2025) 108257`），块数 711 → 680，含页眉的章节 9 → 0。图片型课件 97 块 / 1 章完全不变（PPT 没有页眉）。期刊名还残留 1 次 —— 那是在首页标题区中部出现的，按第 4 条豁免，属于正确行为。

## 2026-11-03 补记：出处要能点回原文（`SourceRef` 补 blocks + bbox）

P0-1。`SourceRef` 原来只有 `page` + `quote`。前端想"点出处跳到原文并高亮那一行"，光有页码和一串纯文本做不到：同一页几十行里根本找不着位置。而 `verify_refs` 校验的时候**本来就知道** quote 落在哪些块上，只是校验完把这个信息丢了。

落地有三处偏离原草案：

1. **`blocks` 存 `Block.id`，不是页内下标。** 下标是"这一页 blocks 列表里第几个"，跨页重排、页眉摘除、段落合并都会让它漂；`Block.id` 是稳定标识，前端拿 id 反查比按下标可靠，调试时也能直接对上。类型因此是 `list[str]` 而不是草案里的 `list[int]`。
2. **`verify_refs` 返回新对象，不再原样直通。** 原来调用方只关心真假，现在要拿到 enrich 过的 ref。`make_quiz` 里因此必须 `q.source_ref = ok[0]` —— 少这一句，blocks/bbox 全白填，而测试只看"题有没有被丢"是发现不了的（所以 pipeline 的用例专门断言了 `source_ref.blocks`）。
3. **`_reading_order_ok` 不删，保留成 `_locate(...) is not None` 的薄包装。** 旧调用点和旧测试一处不用改；新代码走 `locate_quote`（返回下标列表）和 `_locate`（返回首尾下标）。

变异验证四条（全部击杀）：`locate_quote` 恒返回 `[]`、`_merge_bbox` 只取第一块、`verify_refs` 不写 `blocks`、`_locate` 去掉 y 单调检查。测试 64 → 68。

`bbox` 允许为空：OCR 出来的块、以及没有几何信息的老 JSON 都没有坐标，此时 `blocks` 照样有值，前端退化成"按 id 高亮"即可。这个降级路径是故意留的，不是漏写。

## 2026-11-03 补记：界面拆成静态文件（`app/web/`）

P0-2。原来整个前端是 `app/serve.py` 里一个 7743 字符的三引号字符串，改一行 CSS 要在 Python 字符串里找位置，没有语法高亮、没有缩进保护。现在拆成 `app/web/index.html`（1562 字节）、`app/web/app.css`（1910）、`app/web/app.js`（4500），`serve.py` 从 505 行降到 325 行。

两处没有照草案做：

1. **没用 `StaticFiles`，自己写 `GET /static/{name}`。** 想要的是"每个响应都带 `cache-control: no-cache`"——本地开发是边改边刷的，缓存住一个旧 `app.js` 会让人以为改的代码没生效。`StaticFiles` 不方便逐响应插头。越界靠 `path = (WEB_DIR / name).resolve()` + `if WEB_DIR not in path.parents: 404` 拦，比字符串前缀比较靠谱（`..`、软链、大小写都会在 `resolve()` 之后现形）。
2. **MIME 类型写死成 `WEB_TYPES` 表，不交给 `mimetypes` 猜。** Starlette 的 `FileResponse` 在 `media_type=None` 时会 `guess_type(path)`；Windows 上 `mimetypes` 会去读注册表，某些机器把 `.js` 登记成 `text/plain`，浏览器的严格 MIME 检查直接拒绝执行——页面能出来，按钮全不响应，而且控制台只说一句 "refused to execute script"。这类故障排查成本远高于写三个常量的成本。

**踩到的坑（值得记）**：第一版测试把 `mimetypes.guess_type` 打桩成 `text/plain`，以为能守住"类型不随系统变"，结果变异 `media_type=None` 照样存活 —— 因为 Starlette 是 `from mimetypes import guess_type`，早把函数对象接到了自己模块里，改 `mimetypes.guess_type` 对它无效。要打在 `starlette.responses.guess_type` 上。**打桩要打在使用方，不是定义方。**

变异验证四条（全部击杀）：去掉越界检查、`media_type=None`、去掉 no-cache、首页不引 css。测试 68 → 72。

## 2026-11-03 补记：三栏界面 + 点出处高亮原文

P1-1。前端从"一个表单 + 一个 `<pre>`"变成三栏：左目录、中讲义、右原文。核心动作只有一个——**点讲义里的「原文 pN」，右边滚到那一行并高亮**。

实现里几个决定：

1. **原文走文字版，不上 pdf.js。** `Block` 已经有 `id / kind / text / bbox`，按阅读顺序摊开就是一页原文了；pdf.js 要额外 1 MB 的库、要处理渲染时序、还要再把 bbox 映射到画布坐标系。而这个产品的卖点是"每句话能点回原文"，不是"还原排版"。文字版还顺便让全文可搜索、可复制。等真需要看公式和插图再上方案 B。
2. **`GET /api/docs/{id}/layout` 是独立端点，不在讲义结果里塞原文。** 讲义结果只有几十 KB，原文 680 块有 200 KB；一次解析、多次生成，原文没必要每份讲义都复制一遍。前端解析完取一次缓存住，之后按章节页号筛。
3. **块 id 当面元，不当索引。** `source_ref.blocks` 存 `Block.id`（上一轮 P0-1 定的），前端直接 `data-id` + 查表，不关心块在数组里第几个。这也是当时把 `list[int]` 改成 `list[str]` 的理由兑现的地方。
4. **Markdown 只认四种语法。** 段落、`#` 标题、`-` 列表、`**粗体**`（外加行内代码）。讲义里会大量出现 `$v = \lambda / T$` 这类公式，任何"聪明"的渲染都可能把它吃掉；现在 `$…$` 原样当文本显示，错得诚实。渲染前先 `esc()` 转义，再套标签，不拼未转义的用户/模型文本进 HTML。
5. **右侧显示的页 = 本章页 ∪ 所有出处落在的页。** 出处可能引用到章节边界之外的页（模型挑句子时不受章节约束），只按章节页筛会出现"点了没反应"。

验收：真服务上传 15 页综述 → 解析 4.6 秒 → 680 块；`/layout` 也是 15 页 680 块；拿上一份讲义的 **37 条出处**去 layout 里逐个查 id，**0 条缺失**。测试 72 → 76，变异四条全部击杀（页号过滤失效 / 未解析不报 409 / 页号解析恒 None / 块不带 kind）。

**公式**：上一轮「`$…$` 原样当文本显示，错得诚实」这条决定到此作废，换成真渲染。

1. **本地 vendor，不走 CDN。** `app/web/vendor/katex/`（`katex.min.js` 273 KB + `katex.min.css` + `auto-render.min.js` + 20 个 `woff2` 共 548 KB）。理由是主人要"换台电脑也能用"——那台机器可能没网、也可能连不到 jsDelivr。代价只是仓库大 0.5 MB。
2. **静态路由改成 `/static/{name:path}`。** 原来的 `{name}` 只吃一段，`vendor/katex/fonts/*.woff2` 根本够不到。越界检查原样保留（`WEB_DIR not in path.parents` → 404）。
3. **`.woff2` 要显式登记 MIME。** 表里漏了它，浏览器会按 octet-stream 处理，公式直接排成一排方框；`tests/test_serve.py` 里因此有一条断言 `content-type: font/woff2` 且文件头是 `wOF2`。
4. **`throwOnError: false` + `errorColor`。** 一个坏公式不该让整段讲义白屏，坏的那处标红显示原文，人一眼就知道是模型写歪了。
5. **只认 `$…$` / `$$…$$` / `\(…\)` / `\[…\]` 四种定界符**，顺序上 `$$` 先试。已知风险：正文里出现两个孤立的 `$`（比如标价）会被当公式；本项目的文本是课件正文，实测 26 条行内公式里没有这种误伤，先接受。

**习题**：答案默认藏起来，选项可点，提交才判分。

1. **判分规则单独成文件 `app/web/grade.js`，纯函数、不碰 DOM。** 放在 `app.js` 里就只能靠手点验证；拆出来以后浏览器里是 `window.Grade`，node 里 `require` 得到同一份实现，`tests/test_web.py` 直接用 node 跑断言。这是这一轮唯一新增的测试形态（项目本来只有 pytest），换来的是"多选顺序无关""全角 ＡＣ 也认""填空先掏空白"这些规则真的被钉住。
2. **单选点一下就换，多选点一下加一个**；已经判过的题锁死，要重来点「再做一次」。
3. **「看答案」不判分也算一种出口**——主人自己想先看答案时不该被迫作答。
4. **填空题按文本比，`/` 或 `|` 分隔的多种写法命中任意一个都算对**（`牛顿|Newton`）。这道题的答案是模型写的自由文本，不做归一化就几乎必然判错。
5. **没作答时提示"先选一个"，不算答错。** 判错和没答是两件事，混在一起会让人以为自己选错了。

验收：87 条测试全绿（原 76 + 判分 7 + 静态资源 4）；变异四条全部击杀（多选不排序 / 填空不掏空白 / 静态路由退回单段 / MIME 表去掉 woff2）；真服务下 `/` `/static/grade.js` `/static/vendor/katex/katex.min.js` `/static/vendor/katex/fonts/KaTeX_Main-Regular.woff2` 全部 200 且 MIME 正确；用 vendored 的 KaTeX 在 node 里渲染 `\lambda = u T = \frac{u}{\nu}`，产出 `mfrac` 与希腊字母，坏公式返回 `katex-error` 而不抛异常。

## 2026-11-03 补记：失败要说人话、任务要能停

1. **错误分类单独成模块**（app/errors.py）：StudyError 带 kind / title / hint 三个类属性，
   子类覆盖它们。前端直接拿 error_info 显示 title + hint，detail 只在 kind == unknown 时露出来。
   理由：原来所有失败都是一句 str(exc)，用户分不清「是不是我配置错了」和「是不是模型抽风」。
2. **openai 的异常按类名 + status_code 双判据收敛**，不 import openai 的具体类。理由：它换版本改类名很常见，
   而 HTTP 状态码是稳的；两条判据任一命中就能给出人话。
3. **取消与成本闸都放在 LLM._check() 里，且在调用之前**：should_stop() 为真抛 Cancelled，
   次数/token 到顶抛 BudgetExceeded。代价是 token 上限最多超出一次调用的量，换来的是「停下时立刻停，
   不再多花一次钱」。解析路径（extract_ir）每页查一次，因为 OCR 一本扫描件要一两分钟。
4. **上限写歪了不能把服务带崩**：_limit() 读不到或不是正整数就退回默认值（LESSON_MAX_CALLS=40 /
   LESSON_MAX_TOKENS=200000）。配置错误的表现应该是「按默认跑」而不是「起不来」。
5. **对已结束的任务点停返回 200 但不改状态**：前端不需要先判断任务活没活，少一个竞态分支。

## 2026-11-03 补记：历史记录要有索引

1. **索引就是一个 JSON 文件（`out/index.json`），不上 sqlite**：几百条记录，整份读重写更简单，
   也不用处理并发连接。数据量真涨到万级再换。
2. **id 由 `sha1(doc_id + chapter)` 的前 12 位决定，不随机**：同一份 PDF 的同一章重新生成就是覆盖，
   不会在 `out/` 里堆出十个同名文件；`created` 保留第一次的时间，`updated` 每次刷新。
3. **写入走 `index.json.tmp` + `os.replace`**：中途崩了或断电，要么是旧的完整索引，要么是新的完整索引，
   不会留下半截 JSON 把整个历史读崩。
4. **坏索引当空索引用**：JSON 解析失败、顶层不是 list，一律返回 `[]`，下次 `put()` 时重排。
   表现是「历史空了」而不是「服务起不来」—— 这个文件的地位是缓存，不是账本。
5. **记录里的 `file` 只取文件名**（`out_dir / Path(file).name`）：记录被写成 `../secret.json` 也读不到外面。
   索引是本地文件，但它迟早会被别人写的脚本碰，边界要在读的地方守。
6. **记录在、文件被手删 → 410 而不是 500**：`410 讲义文件被删了，重新生成一次` 说的是「这份没了，去重做」，
   500 只会让人以为服务坏了。前端拿到 410 直接把这条从列表里划掉。
7. **打开旧讲义时原文栏可能没有内容**：`doc_id` 是内存里的，重启后旧记录只能看讲义。
   前端拿 `record.doc_id === docId` 判断，对不上就明说「原 PDF 已经不在内存里了」，
   不假装高亮、也不留一个点了没反应的出处按钮。

## 2026-11-03 补记：怎么让别的人/别的机器也能跑

1. **探活接口不许碰重东西**：`/api/health` 只读内存里的计数器和环境变量（外加一次索引文件读取），
   不解析 PDF、不调模型。它要能被监控每秒打一次而不产生任何副作用。
2. **索引读失败时 `lessons` 记 -1，但 `ok` 还是 true**：探活的语义是「进程活着、能接活」，
   不是「所有缓存都完好」。把缓存状态混进存活判定，会让一次手误编辑 `index.json` 变成「服务挂了」的告警。
3. **日志只在 `main()` 里挂，不在 import 时挂**：测试会 import `app.serve` 几十次，
   import 时写盘等于每次跑测试都往 `out/` 里塞日志；而且 `pytest` 的临时目录一删，
   handler 还攥着已经被删的文件句柄。`setup_logging()` 显式调用 + 幂等（同一个文件不会挂两个 handler）。
4. **日志按请求记，但把噪声挡掉**：静态资源和 SSE 心跳（0.4 秒一帧）全记会把日志刷成瀑布，
   只在 4xx/5xx 时记它们。正常请求一行 `方法 路径 -> 状态 耗时`，出问题能顺着时间点对回去。
5. **启动脚本先做体检再起服务**：`.venv` 不在、`.env` 不在、端口被占，这三件事都在起服务之前查，
   并且说清楚下一步做什么。端口那条尤其重要 —— 旧进程没退干净时，页面（每次读盘）看着是新的，
   接口却是旧的，不点明这一点会浪费半小时。
6. **README 写"为什么"，不只是"怎么做"**：venv 必须 3.12（onnxruntime 没 3.15 轮子）、
   原文栏的公式为什么可能认错、为什么习题会一题都没有 —— 这些是踩过才知道的，
   不写下来下一个人（或三个月后的我）会当成 bug 重新查一遍。

## 2026-11-03 补记：`.hide` 这条规则缺了一整个下午

现象：主人截图过来，习题的「答案 B + 解析 + 原文 p10」在**答题前**就摆在页面上。

根因：`app.css` 里根本没有 `.hide { display: none }` 这条规则。HTML 和 JS 里十几个地方
靠 `class="... hide"` 隐东西（进度条外壳、停按钮、习题的答案解析、再做一次），
类名写着、样式却没有 —— 于是全都从头显着，**而且不报任何错**：
CSS 的"类名没有人定义"和"故意不写样式"在浏览器里长得一模一样。

补充两点教训：

1. **纯前端 bug 逃过了 128 条测试**。测试全在 Python 侧和 `grade.js` 的判分逻辑上，
   没有任何一条看过"初始状态下该藏的东西是不是藏着"。现在补了两条：
   `test_stylesheet_actually_hides_the_hide_class`（直接正则盯住那条规则，不看具体元素）和
   `test_quiz_hides_answers_until_the_student_answers`（`.qans` 初始必须带 `hide`，判分后摘掉）。
2. **显隐只留一个开关**。以前有过 `#stop`、`#pBarWrap` 各自 `classList.toggle` 的写法，
   一旦 `.hide` 失效，"该藏"这件事就只剩约定、没有机制。现在所有隐藏都走同一个类名，
   并在那条规则上写了注释解释为什么不能删。

顺手做了一次 class 体检：把 HTML/JS 里出现的 class 和 CSS 里定义的规则对了一遍，
`hide` 是唯一一个真缺的（`qgo`/`qshow`/`qreset` 由 `.qbar button` 兜着，`.k-*` 是有意不给样式）。


## 2026-11-03 补记：设置界面（接谁的模型，不该去翻 `.env`）

1. **配置放 `settings.json`，不放数据库**：就四个字段（接入地址 / 密钥 / 模型 / 思考等级），
   原子写（`.tmp` + `os.replace`）比为了它引一层 sqlite 划算。文件读坏了当空 —— 配置坏不该让服务起不来。
2. **优先级是 `settings.json` > `.env` > 空，且空串等于"没设置"**。
   界面上把密钥清空要能"交还给 `.env`"，而不是把整份配置写坏。
3. **密钥永远不回明文**：`GET /api/settings` 只回 `has_key` 与尾四位（`sk-…ec75`）。
   这既是习惯问题也有实际理由 —— 这个接口会被浏览器缓存、被日志记下。
4. **每个字段都标来源**（`source.{base_url,api_key,model}` = `settings` / `env` / 空）。
   没有这一行，"我明明在界面上改了怎么没用"就只能靠猜。
5. **思考等级做了降级**：不是所有模型都认 `reasoning_effort`。第一次被拒就摘掉参数重发一次，
   记 `llm.reasoning_note`。宁可少一个功能，也不要一个"看起来开着其实没开"的开关。
6. **只有"像是不认这个参数"的报错才降级**（报错里含 reasoning / thinking / effort）。
   放宽了会把真正的 400 吞成"重试一次"，白花一次钱还查不出原因。
7. **改完不用重启**：`_missing()` 与 `effective()` 每次现读。设置是"下一次生成"的参数，
   不是"下一次启动"的参数。


## 2026-11-03 补记：颜色栏与可折叠的原文栏

1. **先色板化，再做颜色栏**。样式表里 62 个颜色字面量、成体系的 81 处换成了 CSS 变量；
   不这么干，"自定义颜色"只能覆盖三五个选择器，剩下的硬编码会把整体配色拖回原样。
2. **浅色主题只覆盖变量，不动任何规则**。规则里再写一遍颜色，两套主题迟早会各长各的。
3. **主题存 `localStorage`，不进 `settings.json`**。换皮是这台电脑、这块屏幕的事；
   而且它要赶在首屏之前生效 —— 走一次网络请求就一定闪。
4. **`<head>` 里那段内联脚本是必要的丑**：主题必须在第一次绘制前套上。
   逻辑仍然只有一份（`app.js` 的 `applyTheme`），内联那段只做"早一步"。
5. **自定义用内联变量，切模式前要清**。内联优先级最高，不清就会"切回深色但背景还是自定义的"。
6. **收起原文后点出处要先展开**：`scrollIntoView` 打在 `display:none` 上是无声失败，
   表现成"点了没反应"，最难查的那类 bug。
7. **折叠状态记在本地**：这是操作习惯，不是配置，不该出现在设置界面里。

## 2026-11-03 补记：浅色读不清、按钮太小、模型换不了

主人用了半天给出的三条反馈，两条是"看着不舒服"，一条是真不会用。

1. **浅色主题的文字太淡**：根因不是色板选得浅，是**还有一整套字面量颜色没被色板收编** —— `app.css` 里剩下的 20 处 `#b8c8da`（小节标题）、`#cbb98a`（易错点）、`#7fb3dd`（出处标签）、`#dcebf9`（选中选项）这些原本都是"深底上的浅字"，换成白底之后就成了白纸上的浅灰蓝。第一次色板化（81 处）只换了成体系的背景/边框/正文，这些零散的角色色全漏了。
   修法：补七个角色变量（`--chip-*`、`--opt-on-*`、`--bad-bg/fg`、`--btn-*`、`--top-line`），深色值照抄原来的字面量（观感不变），浅色值重新挑。**判断标准写成测试**：`test_light_theme_text_is_dark_enough_to_read` 用 WCAG 相对亮度算 `fg/dim/dim2/dim3` 在 `panel` 与 `bg` 上的对比度，要求 ≥10/7/6/5。有了这条，以后调色板不会再把字调糊。
2. **设置按钮太小**：`13.5px` 的字、`7px` 的内边距，一颗瓜子大小。改成 `17px` + `12px 22px`，加了投影，`:hover` 时边框变强调色。测试守 `font-size ≥16`、内边距 ≥10/18、标签 ≥14。
3. **"模型无法切换"**：**服务端一直是好的** —— 实测 `POST /api/settings {"model":"deepseek-v4-pro"}` → `GET /api/config` 立刻回 `deepseek-v4-pro`。坏在前端形态：模型是个 `<input list>` + `<datalist>`，datalist 在 Chromium 里不给可点的下拉箭头，必须点进输入框手打全名，等于"换不了"。
   修法：换成真的 `<select>`，`fillModels(models, current)` 用接口返回的 `/models` 填 `<option>`（当前模型不在列表里也要插到第一位 —— 否则切换后下拉显示空白），末尾永远追加「手动填写…」，选中它才露出自由输入框；`saveSettings` 用 `pickedModel()` 取值。测试守 `select` 存在、`datalist` 必须消失、`MANUAL`/`pickedModel` 在、`select` 被收进 `.field` 的样式（否则是浏览器默认白块）。

**教训**：色板化不能只换"看起来成体系"的那批颜色，**要按角色全收**；剩下的每一个字面量都是一颗定时炸弹，只有在换主题那天才响。同理，"接口对了"不等于"能用了" —— 数据流正确、控件形态错了，用户看到的仍然是"坏了"。
