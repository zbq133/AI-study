## 2026-11-02 补记：两条铁律怎么落到代码里

1. 「独立解题验证」升级为**两次独立解**：第一次按原顺序，第二次把选项左旋一位再解，两次必须指向**同一个选项内容**（不是同一个字母）。同模型重解只能证明自洽，打乱顺序才能查出「按位置蒙」的题。理由：验证器与被验证者是同一个模型，一致性不等于正确性，打乱是零成本能拿到的那一半证据。
2. 答案抠取加正则：验证模型常回「答案是 B」「B. 乙」，原来直接 `.strip().upper()` 比对会把**合格题误杀**。现在从自由文本里收字母串，越界字母作废；填空题没有选项可打乱，按去掉空白后的文本比对，不走字母抠取。
3. 引用校验加**行序检查**（`schema._reading_order_ok`）：同一页里行的 y 坐标应一路往下走，出现大幅回跳只可能是换了栏或跳到了另一段 —— 双栏排版里「左栏末尾 + 右栏开头」拼成一句正好是子串，但那是两处文字，必须丢。这是「不许拼接两处」从提示词挪进代码的部分。同栏相邻两行的边界拼接仍无法与合法引用区分，接受这个边界。
4. 新增测试一律做**变异验证**：把 y 容差关掉、把打乱换成恒等置换、把填空换回字母抠取，对应用例必须变红，否则视为无效测试。
## 2026-11-02 补记：第一份真 PDF 跑通时暴露的三个问题

用 `C:\Users\13304\Desktop\预处理\废旧锂离子电池预处理回收中正极材料释放的最新综述.pdf`（15 页 / 89K 字符 / 22 条书签 / 595pt 双栏）做第一次真文件体检，26 个测试全绿也挡不住的三处：

1. **没有文字层时静默返回空 IR**。同目录的 `第十章 波动.pdf` 是 PPT 导出的图片型课件（12 页，每页一张 960×540 图，text=0），`_page_lines` 里 `type != 0` 把图片块全跳过 → 0 块 → 0 章节 → CLI 打印空表还退出 0，像"解析成功但文件没内容"。现在 `extract_ir` 抛 `NoTextLayer`，CLI 返回 4。**图片型课件是教材场景的主流输入，OCR 是第 2 期必须项，不是可选项。**
2. **TOC 一条也命中不了**。出版方书签写 `1 Introduction`，正文写 `1. Introduction`，原来拿 `normalize`（只去空白）当键 → 22 条书签全部失配，层级退化成字号启发式。改成 `_toc_key`（额外剥掉编号点号、括号、斜杠）后 15 个正文章节标题全部命中，L2/L3 层级回来了。
3. **标题长度阈值 42 是死线**。`11. Development of novel and easily degradable binder` 是 53 字符，被 `short = len(clean) <= 42` 挡在标题之外 → 上一节 `10. Heat treatment` 一路吞到 p11，232 块 15338 字并进了 `10.` 下面。TOC 命中现在优先于长度启发式，问题消失。教训：**用字符数当长度判据对英文天然不公平**（42 个中文够长，42 个英文字符才 7 个词）。
4. 附带：`section_path` 为空的块（首页页眉、期刊名）原来在章节名里显示成 `__root__`，现在叫 `（正文前）`。

三处修复都做了变异验证（换回旧实现 → 对应用例变红）：`_toc_key`→`normalize`、`NoTextLayer` 关掉、`_ROOT_LABEL`→`__root__`，三条全部击杀。
